\section{Object Oriented Design}

%%%% YOUR PART HERE %%%%
% What classes you created, why and how they interact
The classes involved include: 
\begin{itemize}
    
    \item \textbf{BST}. This class uses generics to create binary search trees that store the specified object type as the data in the nodes of the tree. This class is also used to perform operations on that binary search tree, such as insertions, deletions, retrieval of all the data in the tree, changing the value of a key in the tree and finding a node with a specified value in the tree
    \item \textbf{Node}. This is an inner class  of the BST class and is used to represent the nodes stored in the binary search tree. The class is used to store a generic data item and a link to the left and right nodes from that node. 2 nodes can be compared using the Node class, and the data in the node can be retrieved
    \item \textbf{Video}. This class represents a video the user can create to store the 'file name', 'description' and the 'number of likes' that video has in one object. The class can also be used to retrieve or do operations on these attributes
    
    \item \textbf{Profile}. This class represents a Profile object, storing the 'account name', 'description', 'their created videos', 'the other profiles they follow' and 'the videos they like'. This class is also used to perform operations on these attributes and retrieve them. 

    \item \textbf{TokTik}. This class has the main method to run the user interface and create the objects to make the application work. The class displays TokTik to the user and is also used to validate data inputted by the user.
    
\end{itemize}
These classes interact with the other classes as follows:
\begin{itemize}
    \item \textbf{BST} uses \textbf{Node} as its head node and any data insertion creates a node object. Node objects are also used to find data, delete data and get all the data in the tree
    
    \item \textbf{Node} uses \textbf{Node} to store links to the left and right nodes and compare 2 different node objects
    \item \textbf{Video} uses \textbf{Video} to compare 2 different video objects
    \item \textbf{Profile} uses \textbf{Profile} to store a list of profiles that profile follows. Profile objects are also used to compare 2 profiles, unfollow and follow a profile, get a profiles followers (which also uses \textbf{BST} of profiles), and create a new profile off of an old profile with a new username
    
    \item \textbf{Profile} uses \textbf{Video} to store video objects for the videos that profile has created. The videos are stored using \textbf{BST}, by creating a tree object storing video objects
    \item \textbf{Profile} also uses \textbf{Video} in a List to store the liked video. Video objects are also used to like a video, add a video to the BST of videos and display content about a video of a profile
    \item \textbf{TokTik} uses \textbf{Profile} and \textbf{BST} to create a binary tree of with profile objects as the data in each node. \textbf{TokTik} therefore uses \textbf{Profile} to create profile objects and \textbf{Video} to create video objects. 
    \item \textbf{TokTik} uses  \textbf{Node} during validation to check if a found Node object is part of its associated tree (the tree could be the tree of profiles, or tree of videos for a profile).
    
\end{itemize}

\section{Additional Features}
The following features relating to the program as a whole have been implemented:
\begin{enumerate}
    \item Data is validated before accepted. The implemented criteria is:
    \begin{itemize}
        \item A username/file name must be unique
        \item A username/file name cannot contain any spaces
        \item A username/file name cannot be empty
        \item A description cannot be empty
        \item A description cannot be made of only spaces
        \item The number of likes must be an integer
        \item When a list of options is provided, the integer entered must be a valid option for that given list
    \end{itemize}
\end{enumerate}
User-specific features have also been implemented. First, a user can sign into their profile, and after that, they can do one of the following:
\begin{enumerate}
    \item A user can now follow another user and view the users they follow
    \item A user can unfollow a followed user
    \item A user can browse content: A user can either be in 'for you' mode, which when selected, displays a random video from any other profile to the user, or the user can be in 'following' mode to view content only from users that they have followed. This takes a random video from the following users and displays that video
    \item When content is displayed, the option to like the video comes up and should the user like the video, the likes on that video increase and that video is stored in a list of liked videos
    \item The user can update their user settings:
        \begin{itemize}
            \item They can change their username (this is validated and must not be taken)
            \item They can change their description (this is validated)
        \end{itemize}
    \item The user can get a list of their followers (the users who follow them)
    
    \item A user can get a list of liked videos
    \item A user can get a list of their own videos
\end{enumerate}
